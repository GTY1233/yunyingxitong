# 开发实施计划

## 1. 总体策略

开发分两条线推进：

- 产品可视化线：先用前端原型把完整业务结构和链路呈现出来。
- 系统工程线：再用后端服务、任务系统、AI 适配层和平台适配层逐步替换模拟数据。

第一版不追求直接打通所有外部平台，但必须把核心架构做成可以升级到自动化的形式。

## 2. 前端原型阶段

目标：

- 快速看到产品效果
- 验证信息架构（待办 + 商品运营台优先）
- 验证核心操作链路（单页闭环）
- 提前发现页面和业务关系问题

交付内容：

**一级页面：**

- 待办收件箱
- 商品运营台（生成 + 预览 + 发布内嵌）
- 发布中心

**二级页面（更多）：**

- 全量成品库
- 生成任务中心
- 平台账号管理
- 库存中心
- 数据中心

技术要求：

- 可以先使用静态前端和模拟数据
- 保持组件和数据结构接近真实后端
- 状态、任务、成品版本不能写成纯展示
- **以运营人员日活路径设计导航**，避免功能模块堆砌
- 页面布局要适合运营人员长期使用，避免营销页风格

## 3. 后端基础阶段

目标：

- 建立真实业务数据
- 提供前端可调用 API
- 建立任务和日志基础

服务划分：

- ProductService 商品服务
- AssetService 成品服务
- GenerationTaskService 生成任务服务
- ListingService 上架服务
- PublishService 发布服务
- AccountService 平台账号服务
- InventoryService 库存服务
- WorkflowService 流程服务
- OperationLogService 日志服务

基础能力：

- 商品 CRUD
- 成品上传和管理
- 任务创建和状态更新
- 成品预览发布
- 上架草稿
- 发布任务
- 库存校验
- 操作日志

## 4. AI 能力接入阶段

目标：

- 将模拟生成替换成真实 AI 生成
- 生成过程异步化
- 生成结果自动入成品库

接入顺序：

1. 文案生成
2. RunningHub 图片生成
3. RunningHub 视频生成

设计要求：

- 前台不暴露 RunningHub
- 后端通过 AIAdapter 调用外部能力
- 每次调用都生成 GenerationTask
- 输入和输出都要留痕
- 失败要有错误原因和重试机制
- 生成结果必须版本化

### 前端体验要求（与 AI 接入并行）

- 生成 API 调用入口集中在 **商品运营台**，不在多个一级页面重复
- 任务轮询时刷新运营台内任务区，避免强制跳转
- 待办项由 Product / Asset / GenerationTask 状态聚合生成

## 5. 工作流阶段

目标：

- 从单任务操作升级为自动化流程
- 支持节点状态和人工确认节点（预览后发布）

核心能力：

- 创建流程实例
- 节点顺序执行
- 节点失败处理
- 节点等待人工确认
- 确认后继续
- 支持人工跳过节点
- 支持终止流程
- 支持批量流程部分成功

第一批流程模板：

- 新品半自动流程
- 只生成成品流程
- 批量商品处理流程
- 多账号发布流程
- 库存联动流程

## 6. 平台接入阶段

目标：

- 逐步接入真实平台能力
- 不让平台差异污染主业务

平台能力分级：

- L1：只能导出素材，人工发布
- L2：可创建发布草稿或辅助发布
- L3：可自动发布内容
- L4：可自动上架商品
- L5：可回流完整数据

平台适配层：

- DouyinAdapter
- XiaohongshuAdapter
- TaobaoAdapter
- PinduoduoAdapter
- WechatChannelAdapter
- KuaishouAdapter

每个平台单独适配，主业务只依赖统一接口。

## 7. 库存和数据阶段

目标：

- 让库存真正影响运营动作
- 让发布和商品表现可以回流

库存能力：

- 手动库存
- 批量导入
- 平台同步
- 库存预警
- 上架前检查
- 发布前检查
- 售罄自动暂停发布

数据能力：

- 商品曝光、点击、成交
- 内容播放、点赞、评论、收藏、转发
- 商品点击和转化
- 账号发布成功率
- 自动化成功率
- 生成失败率
- 发布成功率

## 8. 测试计划

测试重点：

- 待办聚合与跳转上下文（商品 ID、成品 ID）
- 商品运营台单页闭环（生成 → 预览 → 发布）
- 商品创建和弱信息创建
- 成品版本保存
- 生成任务成功和失败
- 上架草稿字段校验
- 发布任务创建和状态变化
- 库存不足拦截
- 批量任务部分成功
- 异常任务重新执行
- 日志记录完整性

自动化测试优先覆盖：

- 数据模型
- 状态流转
- 任务重试
- 库存拦截
- 成品发布流转

## 9. 近期执行顺序

近期按以下顺序推进：

1. 完成项目文档
2. 完成静态可交互原型
3. **UX 重构：待办 + 商品运营台**（已完成 v1）
4. 根据链路反馈调整页面
5. 明确技术栈
6. 设计后端接口
7. 实现商品、成品、任务、发布基础服务
8. 接入真实 AI 生成
9. M6：素材包导出 + 字段完整性
10. 增加工作流执行器
11. 接入平台账号和发布能力
12. 逐步升级到自动化运营
