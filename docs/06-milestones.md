# 产品完整里程碑

## M0：产品蓝图与静态 MVP

状态：已完成。

目标：

- 明确产品方向
- 建立产品文档
- 完成可交互前端 MVP
- 跑通商品、生成、审核、发布、库存的模拟闭环

交付：

- 产品原则
- MVP 范围
- 核心数据模型
- 业务链路与状态机
- 信息架构
- 开发实施计划
- 静态前端原型
- GitHub 仓库

## M1：真实数据 MVP 基座

目标：让系统从“能看”升级为“能存、能改、能查”。

核心内容：

- 后端项目初始化
- 数据库设计
- 商品管理接口
- 素材管理接口
- 审核任务接口
- 发布任务接口
- 库存接口
- 操作日志接口
- 前端从模拟数据切换到真实 API

验收标准：

- 可以真实创建商品
- 可以上传或登记素材
- 商品详情能从数据库读取
- 审核、发布、库存状态能真实保存
- 刷新页面后数据不丢失

## M2：任务系统与异步生成基座

目标：为 RunningHub 和后续自动化做准备。

核心内容：

- 生成任务表
- 任务状态机
- 任务队列或轮询机制
- 失败重试
- 任务日志
- 任务详情页
- 图片、文案、视频任务统一抽象

验收标准：

- 用户点击生成后，会创建真实任务
- 任务有待执行、执行中、成功、失败等状态
- 失败可以重试
- 任务结果可以进入素材库

## M3：AI 文案生成接入

目标：先接成本最低、反馈最快的生成能力。

核心内容：

- 商品标题生成
- 卖点生成
- 详情文案生成
- 视频脚本生成
- 发布文案生成
- 多版本生成
- 保存、编辑、加入审核

验收标准：

- 选择商品后能真实生成文案
- 生成结果绑定商品
- 文案能进入审核
- 审核通过后能用于发布任务

## M4：RunningHub 图片生成接入

目标：接入真实 AI 图片生成。

核心内容：

- 图片生成模板
- 主图生成
- 详情页图生成
- 卖点图生成
- 封面图生成
- 结果保存
- 版本管理
- 失败重试

验收标准：

- 商品图片可以发起生成
- RunningHub 返回结果后进入素材库
- 每次生成形成版本
- 图片可审核、可设为主图、可用于上架草稿

## M5：RunningHub 视频生成接入

目标：完成核心 AI 视频能力。

核心内容：

- 视频脚本确认
- 商品展示视频
- 图文混剪视频
- 视频封面
- 视频生成任务
- 视频结果预览
- 视频保存与审核

验收标准：

- 商品可以生成真实视频
- 视频生成是异步任务
- 视频失败可重试
- 视频能进入审核和发布任务

## M6：审核流正式版

目标：把自动化里的人工控制节点做扎实。

核心内容：

- 审核队列
- 图片审核
- 文案审核
- 视频审核
- 上架草稿审核
- 发布任务审核
- 驳回、修改后通过、重新生成
- 审核日志

验收标准：

- 所有关键内容都可以进入审核
- 审核结果会影响后续任务
- 驳回后可以重新生成
- 审核记录可追溯

## M7：上架草稿与导出发布

目标：先做平台 API 之前最稳的发布闭环。

核心内容：

- 上架草稿
- 字段完整性检查
- 商品素材选择
- 发布任务创建
- 视频、封面、标题、文案打包
- 导出发布素材包

验收标准：

- 审核通过的素材可以创建上架草稿
- 可以创建发布任务
- 可以导出视频、封面、文案、商品信息
- 即使不接平台 API，也能辅助人工发布

## M8：自动化流程基础版

目标：把单点功能串成流程。

核心内容：

- 流程实例
- 流程节点
- 节点状态
- 自动继续执行
- 审核暂停
- 审核通过后继续
- 失败转异常队列
- 手动跳过或重试

验收标准：

- 可以创建新品半自动流程
- 商品能自动走生成文案、生成图片、生成视频、审核
- 节点失败不会导致全流程失控
- 用户能看到商品卡在哪一步

## M9：平台账号与半自动发布

目标：开始进入真实运营分发。

核心内容：

- 平台账号授权结构
- 店铺账号
- 内容账号
- 账号人设
- 发布规则
- 发布日历
- 半自动发布
- 失败记录

验收标准：

- 商品可以绑定平台和账号
- 不同账号可以生成不同文案
- 发布任务可以按账号排期
- 发布失败有原因和处理动作

## M10：库存联动正式版

目标：让库存真正约束运营动作。

核心内容：

- SKU 库存
- 预警库存
- 库存修改
- 批量导入
- 发布前库存校验
- 售罄暂停发布
- 库存恢复后恢复任务

验收标准：

- 库存为 0 时禁止发布和上架
- 库存低于预警时提示或拦截
- 售罄商品自动暂停待发布任务
- 库存恢复后可恢复任务

## M11：平台 API 接入

目标：逐步接真实平台能力。

平台能力优先级：

1. 导出发布
2. 半自动发布
3. 自动发布
4. 自动上架
5. 数据回流

设计要求：

- 每个平台单独做适配层
- 主业务只依赖统一平台接口
- 某个平台接不了 API，不影响其他能力

验收标准：

- 平台能力可分级
- 发布、上架、回流都走统一任务模型
- 平台失败原因可以进入异常队列

## M12：数据中心与效果回流

目标：让系统知道什么内容有效。

核心内容：

- 商品数据
- 内容数据
- 账号数据
- 自动化数据
- 生成成功率
- 审核通过率
- 发布成功率
- 素材表现对比

验收标准：

- 能看到商品、内容、账号维度表现
- 能知道哪个素材被使用
- 能知道哪个账号发布效果好
- 后续可反向优化生成策略

## M13：自动化运营 V1

目标：实现完整自动化运营链路。

完整链路：

```text
上传商品
→ 自动识别
→ 自动生成图文视频
→ 审核
→ 自动上架
→ 自动创建发布任务
→ 自动发布
→ 自动挂商品
→ 库存联动
→ 数据回流
```

验收标准：

- 用户上传商品后，系统能自动跑主流程
- 人工只在审核和异常处介入
- 失败后可恢复
- 多商品批量流程支持部分成功
- 多账号矩阵可以自动分发

## M14：策略优化与升级扩展

目标：从自动化执行升级到智能运营。

核心内容：

- 高表现素材识别
- 账号风格自动匹配
- 商品内容策略推荐
- 自动生成多账号差异化内容
- 根据数据优化模板
- 批量 SKU 自动运营
- 更复杂的流程编排器
