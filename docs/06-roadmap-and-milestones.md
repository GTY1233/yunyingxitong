# 产品路线图与完整里程碑

## 当前状态

当前项目已完成 M0，并已经进入 M1。

当前阶段不是单纯原型阶段，已经开始从静态演示升级为真实数据基座：

- M0：产品蓝图与静态 MVP，已完成。
- M1：真实数据 MVP 基座，进行中。
- 当前已完成 M1 的第一部分：本地 Node 服务、JSON 持久化、资源接口、业务动作接口、前端 API 调用。
- 当前下一步：补齐真实商品创建、商品编辑、库存编辑和商品详情保存能力。

## 下一步

下一步优先推进 **M1.2：商品录入与编辑能力**。

原因：

- 目前系统已经能通过 API 保存数据，但前端仍有一部分操作是“模拟按钮”。
- 商品是整个系统的中心，必须先让商品资料能真实录入、修改、保存。
- 商品字段、库存、平台、账号等信息稳定后，后续 AI 生成、审核、上架、发布才能可靠串联。

M1.2 交付目标：

- 商品中心支持真实新建商品表单
- 商品详情支持编辑基础字段
- 库存可以手动修改并保存
- 商品目标平台和绑定账号可以编辑
- 页面刷新后编辑结果不丢失
- 所有修改写入操作日志

M1.2 完成后，继续推进 **M1.3：素材登记与审核任务管理**。

## 完整计划总览

完整产品按以下路线推进：

```text
M0 产品蓝图与静态 MVP
→ M1 真实数据 MVP 基座
→ M2 任务系统与异步生成基座
→ M3 AI 文案生成接入
→ M4 RunningHub 图片生成接入
→ M5 RunningHub 视频生成接入
→ M6 审核流正式版
→ M7 上架草稿与导出发布
→ M8 自动化流程基础版
→ M9 平台账号与半自动发布
→ M10 库存联动正式版
→ M11 平台 API 接入
→ M12 数据中心与效果回流
→ M13 自动化运营 V1
→ M14 策略优化与升级扩展
```

## M0：产品蓝图与静态 MVP

状态：已完成。

目标：

- 明确产品方向
- 建立产品文档
- 完成可交互前端 MVP
- 跑通商品、生成、审核、发布、库存的模拟闭环

交付：

- 产品原则
- MVP 范围
- 核心数据模型
- 业务链路与状态机
- 信息架构
- 开发实施计划
- 静态前端原型
- GitHub 仓库

## M1：真实数据 MVP 基座

状态：进行中。

目标：让系统从“能看”升级为“能存、能改、能查”。

核心内容：

- 后端项目初始化
- 数据库设计
- 商品管理接口
- 素材管理接口
- 审核任务接口
- 发布任务接口
- 库存接口
- 操作日志接口
- 前端从模拟数据切换到真实 API

当前已完成：

- 本地 Node 服务
- JSON 文件持久化
- `GET /api/state`
- `POST /api/state`
- 资源接口
- 业务动作接口
- 前端关键动作接入 API
- API 契约文档

当前未完成：

- 商品真实创建表单
- 商品详情编辑保存
- 库存编辑保存
- 账号与平台选择保存
- 更完整的日志展示
- 资源接口的页面级管理能力

验收标准：

- 可以真实创建商品
- 可以上传或登记素材
- 商品详情能从数据库读取
- 审核、发布、库存状态能真实保存
- 刷新页面后数据不丢失

## M2：任务系统与异步生成基座

目标：为 RunningHub 和后续自动化做准备。

核心内容：

- 生成任务表
- 任务状态机
- 任务队列或轮询机制
- 失败重试
- 任务日志
- 任务详情页
- 图片、文案、视频任务统一抽象

验收标准：

- 用户点击生成后，会创建真实任务
- 任务有待执行、执行中、成功、失败等状态
- 失败可以重试
- 任务结果可以进入素材库

## M3：AI 文案生成接入

目标：先接成本最低、反馈最快的生成能力。

核心内容：

- 商品标题生成
- 卖点生成
- 详情文案生成
- 视频脚本生成
- 发布文案生成
- 多版本生成
- 保存、编辑、加入审核

验收标准：

- 选择商品后能真实生成文案
- 生成结果绑定商品
- 文案能进入审核
- 审核通过后能用于发布任务

## M4：RunningHub 图片生成接入

目标：接入真实 AI 图片生成。

核心内容：

- 图片生成模板
- 主图生成
- 详情页图生成
- 卖点图生成
- 封面图生成
- 结果保存
- 版本管理
- 失败重试

验收标准：

- 商品图片可以发起生成
- RunningHub 返回结果后进入素材库
- 每次生成形成版本
- 图片可审核、可设为主图、可用于上架草稿

## M5：RunningHub 视频生成接入

目标：完成核心 AI 视频能力。

核心内容：

- 视频脚本确认
- 商品展示视频
- 图文混剪视频
- 视频封面
- 视频生成任务
- 视频结果预览
- 视频保存与审核

验收标准：

- 商品可以生成真实视频
- 视频生成是异步任务
- 视频失败可重试
- 视频能进入审核和发布任务

## M6：审核流正式版

目标：把自动化里的人工控制节点做扎实。

核心内容：

- 审核队列
- 图片审核
- 文案审核
- 视频审核
- 上架草稿审核
- 发布任务审核
- 驳回、修改后通过、重新生成
- 审核日志

验收标准：

- 所有关键内容都可以进入审核
- 审核结果会影响后续任务
- 驳回后可以重新生成
- 审核记录可追溯

## M7：上架草稿与导出发布

目标：先做平台 API 之前最稳的发布闭环。

核心内容：

- 上架草稿
- 字段完整性检查
- 商品素材选择
- 发布任务创建
- 视频、封面、标题、文案打包
- 导出发布素材包

验收标准：

- 审核通过的素材可以创建上架草稿
- 可以创建发布任务
- 可以导出视频、封面、文案、商品信息
- 即使不接平台 API，也能辅助人工发布

## M8：自动化流程基础版

目标：把单点功能串成流程。

核心内容：

- 流程实例
- 流程节点
- 节点状态
- 自动继续执行
- 审核暂停
- 审核通过后继续
- 失败转异常队列
- 手动跳过或重试

验收标准：

- 可以创建新品半自动流程
- 商品能自动走生成文案、生成图片、生成视频、审核
- 节点失败不会导致全流程失控
- 用户能看到商品卡在哪一步

## M9：平台账号与半自动发布

目标：开始进入真实运营分发。

核心内容：

- 平台账号授权结构
- 店铺账号
- 内容账号
- 账号人设
- 发布规则
- 发布日历
- 半自动发布
- 失败记录

验收标准：

- 商品可以绑定平台和账号
- 不同账号可以生成不同文案
- 发布任务可以按账号排期
- 发布失败有原因和处理动作

## M10：库存联动正式版

目标：让库存真正约束运营动作。

核心内容：

- SKU 库存
- 预警库存
- 库存修改
- 批量导入
- 发布前库存校验
- 售罄暂停发布
- 库存恢复后恢复任务

验收标准：

- 库存为 0 时禁止发布和上架
- 库存低于预警时提示或拦截
- 售罄商品自动暂停待发布任务
- 库存恢复后可恢复任务

## M11：平台 API 接入

目标：逐步接真实平台能力。

平台能力优先级：

1. 导出发布
2. 半自动发布
3. 自动发布
4. 自动上架
5. 数据回流

设计要求：

- 每个平台单独做适配层
- 主业务只依赖统一平台接口
- 某个平台接不了 API，不影响其他能力

验收标准：

- 平台能力可分级
- 发布、上架、回流都走统一任务模型
- 平台失败原因可以进入异常队列

## M12：数据中心与效果回流

目标：让系统知道什么内容有效。

核心内容：

- 商品数据
- 内容数据
- 账号数据
- 自动化数据
- 生成成功率
- 审核通过率
- 发布成功率
- 素材表现对比

验收标准：

- 能看到商品、内容、账号维度表现
- 能知道哪个素材被使用
- 能知道哪个账号发布效果好
- 后续可反向优化生成策略

## M13：自动化运营 V1

目标：实现完整自动化运营链路。

完整链路：

```text
上传商品
→ 自动识别
→ 自动生成图文视频
→ 审核
→ 自动上架
→ 自动创建发布任务
→ 自动发布
→ 自动挂商品
→ 库存联动
→ 数据回流
```

验收标准：

- 用户上传商品后，系统能自动跑主流程
- 人工只在审核和异常处介入
- 失败后可恢复
- 多商品批量流程支持部分成功
- 多账号矩阵可以自动分发

## M14：策略优化与升级扩展

目标：从自动化执行升级到智能运营。

核心内容：

- 高表现素材识别
- 账号风格自动匹配
- 商品内容策略推荐
- 自动生成多账号差异化内容
- 根据数据优化模板
- 批量 SKU 自动运营
- 更复杂的流程编排器
